## Язык описания модели (DSL)

DSL Annette Data Dictionary позволяет декларативно описать все элементы вашей модели данных.

* 🏛️ [Домен (Domain)](#домен): Корневой элемент, описывающий предметную область.
* 📦 [Компоненты (Components)](#компоненты): Иерархическая группировка для декомпозиции крупных моделей.
* 🏷️ [Метки (Labels)](#метки): Гибкий механизм для кастомизации (например, переопределение типа данных поля, указание
  пакета
  Java/Go).
* 📝 [Перечисления (Enums)](#перечисления): Типы с фиксированным набором допустимых значений.
* 🧩 [Элементы данных (Data Elements)](#элементы-данных): Именованные типы с бизнес-семантикой (например, EmailAddress,
  ProductSKU), которые можно переиспользовать в разных таблицах.
* 🧩 [Шаблоны вставки (Includes)](#шаблоны-вставки): Шаблоны для переиспользования групп полей в разных таблицах и
  структурах.
* 🗂️ [Таблицы (Tables)](#таблицы): Описание таблиц, их полей, первичных ключей, индексов и связей с другими таблицами.
* 📊 [Структуры (Structs)](#структуры): Структуры для DTO и операций с данными. Могут наследовать поля у таблиц с
  возможностью исключения или включения полей.

Для описания модели данных необходимо добавить следующие импорты:

```scala
import biz.lobachev.annette.data_dictionary.dsl.DSL.*
import biz.lobachev.annette.data_dictionary.labels.Audit.* // опционально
import biz.lobachev.annette.data_dictionary.labels.ClickHouse.* // опционально
import biz.lobachev.annette.data_dictionary.labels.Go.* // опционально
import biz.lobachev.annette.data_dictionary.labels.Java.* // опционально
import biz.lobachev.annette.data_dictionary.labels.TablePrefixSuffix.* // опционально
import biz.lobachev.annette.data_dictionary.labels.Postgres.* // опционально
```

Если вы используете доменную модель созданную в предыдущих версиях Annette Data Dictionary (< `0.5.0`), то добавьте в
импорт CompatDSL, который обеспечит частичную совместимость:

```scala
import biz.lobachev.annette.data_dictionary.dsl.CompatDSL.*
```

### Домен

**Домен** — это корневой контейнер, который описывает всю вашу предметную область. Он содержит все остальные элементы
модели (таблицы, перечисления, компоненты и т.д.).

📝 **Синтаксис объявления**

Домен объявляется как переменная в Scala. Эта переменная затем используется для сборки итоговой модели.

```scala
val myDomain = domain("id", "name", "description")
  .withLabels(/* метки домена */)
  .withEnums(/* перечисления домена */)
  .withDataElements(/* элементы данных домена */)
  .withComponents(/* вложенные компоненты */)
  .withTables(/* таблицы домена */)
  .withStructs(/* модели данных */)
```

⚙️ **Аргументы и параметры**

| Параметр      | Описание                                                   | Обязательно |
|---------------|------------------------------------------------------------|-------------|
| `id`          | Уникальный идентификатор домена                            | ✅           |
| `name`        | Краткое описание домена                                    | ✅           |
| `description` | Детальное описание (опционально, может быть многострочным) | ❌           |

🧩 **Методы настройки**

| Метод                 | Назначение          | Опционально |
|-----------------------|---------------------|-------------|
| `.withLabels`         | Метки домена        | ✅           |
| `.withEnums`          | Перечисления        | ✅           |
| `.withDataElements`   | Элементы данных     | ✅           |
| `.withComponents`     | Компоненты домена   | ✅           |
| `.withTables`         | Таблицы домена      | ✅           |
| `.withStructs`        | Структуры данных    | ✅           |
| `.withLabeledStructs` | Структуры с метками | ✅           |

💡 **Рекомендации**

* Если модель небольшая, все элементы можно разместить в одном файле.
* Для крупных моделей (десятки и сотни таблиц) рекомендуется **декомпозировать домен на компоненты**:

  ```scala
  .withComponents(
    financeComponent,
    logisticsComponent
  )
  ```

  Это облегчает сопровождение и позволяет распределить ответственность между командами.

> 🔗 См. также: [Компоненты](#компоненты)

### Компоненты

Компоненты позволяют **декомпозировать доменную модель** на отдельные части.
Они могут содержать те же элементы, что и домен: вложенные компоненты, метки, перечисления, таблицы и структуры.

📘 **Пример**

```scala
val comp = component("id", "name", "description")
  .withLabels(/* метки */)
  .withEnums(/* перечисления */)
  .withDataElements(/* элементы данных */)
  .withComponents(/* вложенные компоненты */)
  .withTables(/* таблицы */)
  .withStructs(/* структуры */)
  .withLabeledStructs(/* метки структур */)(/* структуры */)
```

⚙️ **Особенности**

* Компоненты **могут включать другие компоненты**, образуя иерархию.
* Элементы, определённые в одном компоненте (например, `enum` или `dataElement`), могут использоваться в других
  компонентах того же домена.
* Компоненты **не накладывают ограничений** на перекрёстное использование элементов.

### Метки

Метки (`labels`) — это **гибкий механизм настройки генерации артефактов**.
Метка представляет собой пару **ключ–значение**:

```scala
postgresSchema("core")
```

📗 **Виды меток**

| Тип               | Где задаётся                                                      | Пример                      |
|-------------------|-------------------------------------------------------------------|-----------------------------|
| **Прямая**        | На конкретном элементе (поле, таблица)                            | `postgresDataType("uuid")`  |
| **Иерархическая** | На уровне элемента (таблица или структура), компонента или домена | `postgresSchema("finance")` |

🧭 **Механизм поиска иерархической метки**

При генерации артефакта метка ищется **снизу вверх**:

1. На уровне самого элемента (например, таблицы)
2. На уровне компонента, где определён элемент
3. На уровне родительского компонента
4. На уровне домена
   Если метка не найдена — используется **значение по умолчанию**
   (например, схема PostgreSQL `public`).

> 💡 **Пример:**
> Метка `postgresSchema` определяет схему PostgreSQL, где будет создана таблица.
> Если её не задать явно — таблица попадёт в схему `public`.

#### Метки аудита

Метки аудита регулируют генерацию скриптов для аудита базы данных. Метки являются иерархическими.

| Метка                | Описание                                    | Пример                 |  
|----------------------|---------------------------------------------|------------------------|  
| `Audit.audit`        | Определяет наименование таблицы аудита      | `Audit.audit("audit")` |  
| `Audit.disableAudit` | Исключает таблицу и/или компонент из аудита | `Audit.disableAudit()` |  

#### Метки ClickHouse

Метки ClickHouse регулируют генерацию DDL скриптов ClickHouse.

| Метка                           | Описание                                                                                                                         | Пример                                                |  
|---------------------------------|----------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------|  
| `ClickHouse.clickHouseEngine`   | Определяет движок ClickHouse, который будет использоваться при создании таблицы. Иерархическая метка. По умолчанию `MergeTree()` | `ClickHouse.clickHouseEngine("ReplacingMergeTree()")` |  
| `ClickHouse.clickHouseExclude`  | Исключает таблицу и/или компонент из генерации DDL скрипта ClickHouse. Иерархическая метка.                                      | `ClickHouse.clickHouseExclude()`                      |  
| `ClickHouse.clickHouseDataType` | Определяет тип поля таблицы и/или элемента данных. Прямая метка.                                                                 | `ClickHouse.clickHouseDataType("IPv4")`               |  

#### Метки PostgreSQL

Метки PostgreSQL регулируют генерацию DDL скриптов PostgreSQL.

| Метка                       | Описание                                                                                                                   | Пример                               |  
|-----------------------------|----------------------------------------------------------------------------------------------------------------------------|--------------------------------------|  
| `Postgres.postgresSchema`   | Определяет схему PostgreSQL, которая будет использоваться при создании таблицы. Иерархическая метка. По умолчанию `public` | `Postgres.postgresSchema("finance")` |  
| `Postgres.postgresDataType` | Определяет тип поля таблицы и/или элемента данных. Прямая метка.                                                           | `Postgres.postgresDataType("POINT")` |  

#### Метки префиксов/суффиксов таблиц

Метки префиксов/суффиксов таблиц регулируют генерацию наименования таблиц PostgreSQL и ClickHouse добавляя к имени
таблицы префикс или суффикс. Метки являются иерархическими.

| Метка                               | Описание                      | Пример                                       |  
|-------------------------------------|-------------------------------|----------------------------------------------|  
| `TablePrefixSuffix.tableNamePrefix` | Задаёт префикс имени таблицы. | `TablePrefixSuffix.tableNamePrefix("fi")`    |  
| `TablePrefixSuffix.tableNameSuffix` | Задаёт суффикс имени таблицы. | `TablePrefixSuffix.tableNameSuffix("users")` |  

#### Метки Go

Метки Go регулируют генерацию кода сущностей таблиц и структур Go.

| Метка                   | Описание                                                                                       | Пример                                                                           |  
|-------------------------|------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------|

| `Go.goStructPackage`    | Определяет имя пакета для структур. Иерархическая метка. Значение по умолчанию "data_model"    | `Go.goStructPackage("github.com/valerylobachev/finance/logic/model")`            |

| `Go.goEnumPackage`      | Определяет имя пакета для перечислений. Иерархическая метка. Значение по умолчанию "enums"     | `Go.goEnumPackage("github.com/valerylobachev/finance/logic/model")`              |  
| `Go.goDataType`         | Определяет тип поля таблицы и/или элемента данных. Прямая метка.                               | `Go.goDataType("complex64")`                                                     |  

#### Метки Java

Метки Java регулируют генерацию кода сущностей таблиц и структур Java/Scala/Kotlin.

### Перечисления

Перечисления позволяют реализовать типы данных с фиксированным набором допустимых значений.
Возможны следующие виды перечислений:

* нативное - реализуется на уровне PostgreSQL
* строковое - реализуется в виде строкового поля заданной длины `varchar(length)`
* целочисленное - реализуется в виде целочисленного поля

#### Нативное перечисление

Нативное перечисление определяется в виде:

```scala
nativeEnum("id", "name", lengt, "description")
  .withValues(/* значения перечисления */)
```

⚙️ Аргументы и параметры

| Параметр      | Описание                                        | Обязательно |
|---------------|-------------------------------------------------|-------------|
| `id`          | Уникальный идентификатор перечисления           | ✅           |
| `name`        | Краткое описание перечисления                   | ✅           |
| `length`      | Максимальное количество символов в перечислении | ✅           |
| `description` | Детальное описание перечисления.                | ❌           |

Значения перечисления задаются в виде: `<значение> -> <имя константы> -> <описание значения>`

Пример нативного перечисления:

```scala
nativeEnum("LedgerType", "Ledger Type", 1)
  .withValues(
    "L" -> "LeadingLedger" -> "Leading ledger",
    "X" -> "ExtensionLedger" -> "Extension ledger",
  )
```

#### Строковое перечисление

Строковое перечисление реализуется в виде строкового поля заданной длины `varchar(length)`. Строковое перечисление может
быть следующего вида:

* строгое (`strictStringEnum`) - при присвоении значения полю выполняется проверка на допустимость значения
* не строгое (`stringEnum`) - полю может быть присвоено любое значение

Пример:

```scala
stringEnum("LedgerType", "Ledger Type", 1)
  .withValues(
    "L" -> "LeadingLedger" -> "Leading ledger",
    "X" -> "ExtensionLedger" -> "Extension ledger",
  )
```

#### Целочисленное перечисление

Целочисленное перечисление реализуется в виде целочисленного поля. Как и строковое перечисление может быть строгим
`strictIntEnum` и не строгим `intEnum`. Значение перечисления должно быть целочисленным значением.

Перечисление определяется в виде:

```scala
intEnum("id", "name", "description")
  .withValues(/* значения перечисления */)
```

⚙️ Аргументы и параметры

| Параметр      | Описание                              | Обязательно |
|---------------|---------------------------------------|-------------|
| `id`          | Уникальный идентификатор перечисления | ✅           |
| `name`        | Краткое описание перечисления         | ✅           |
| `description` | Детальное описание перечисления.      | ❌           |

Пример:

```scala
intEnum("LedgerType", "Ledger Type")
  .withValues(
    "0" -> "LeadingLedger" -> "Leading ledger",
    "1" -> "ExtensionLedger" -> "Extension ledger",
  )
```

### Элементы данных

Элементы данных (Data Elements) - это именованные типы с бизнес-семантикой (например, CompanyCodeId, ProductSKU),
которые можно переиспользовать в таблицах и структурах.

Элемент данных может быть задан в двух форматах:

```scala
// новый формат 
"id" :! "field name" :> "db field name" :# datatype :@ "name" :@@ "description" :* ( /* метки элемента данных */ )

// старый формат 
dataElement("id", "field name", datatype, "name")
  .withLabels(/* метки элемента данных */)
  .withDbFieldName("db field name")
  .withDescription("description")

```

⚙️ Аргументы и параметры

| Параметр        | Описание                                 | Обязательно |
|-----------------|------------------------------------------|-------------|
| `id`            | Уникальный идентификатор элемента данных | ✅           |
| `field name`    | Имя поля                                 | ✅           |
| `db field name` | Имя поля в базе данных                   | ❌           |
| `datatype`      | Тип данных                               | ✅           |
| `name`          | Наименование (краткое описание)          | ✅           |
| `description`   | Детальное описание                       | ❌           |

Пример:

```scala
// новый формат элемента данных
"UserId" :! "userId" :# varchar(20) :@ "User Id" :@@ "description"


// старый формат элемента данных
dataElement("CreditorId", "creditorId", varchar(10), "Creditor id")
  .withLabels(/* метки элемента данных */)
  .withDescription("description")
```

### Шаблоны вставки

Шаблоны вставки (Includes) предназначены для переиспользования групп полей в таблицах и структурах. Если один и тот же
набор полей используется в разных таблицах, то его можно выделить в шаблон вставки и использовать в виде
`include("inclideId")` (в полях таблиц) или `includeStructFields("inclideId")` (в полях структур).

Определение шаблона вставки имеет следующий формат:

```scala
includeDef("id", "name")
  .withDescription("description")
  .withFields(/* описание полей */)
```

⚙️ Аргументы и параметры

| Параметр         | Описание                                                                               | Обязательно |
|------------------|----------------------------------------------------------------------------------------|-------------|
| `id`             | Уникальный идентификатор шаблона вставки                                               | ✅           |
| `name`           | Наименование (краткое описание)                                                        | ✅           |
| `description`    | Детальное описание                                                                     | ❌           |
| `описание полей` | Перечень полей шаблона. Формат описания полей приведён в разделе [Поля](#поля-таблицы) | ✅           |

Пример шаблона для полей модификации записи:

```scala
includeDef("Modification", "Modification data structure")
  .withFields(
    "updatedBy" :# "UserId" :@ "User updated record",
    "updatedAt" :# instant :@ "Timestamp of record update" :== "CURRENT_TIMESTAMP"
  )
```

### Таблицы

Таблицы - ключевой элемент модели данных. Они описываются в следующем формате:

```scala
table("id", "name", "entity name")
  .withTableName("db table name")
  .withDescription("description")
  .withLabels(/* метки таблицы */)
  .withPK(/* определение полей первичного ключа */)
  .withFields(/* определение полей */)
  .withIndexes(/* определение индексов */)
  .withRelations(/* определение отношений */)
```

⚙️ **Аргументы и параметры**

| Параметр        | Описание                                                                                                                         | Обязательно |
|-----------------|----------------------------------------------------------------------------------------------------------------------------------|-------------|
| `id`            | Уникальный идентификатор таблицы. Приводится к PascalCase                                                                        | ✅           |
| `name`          | Наименование (краткое описание) таблицы                                                                                          | ✅           |
| `entity name`   | Имя класса (структуры) сущности. Если не задано, то берётся из `id`.                                                             | ❌           |
| `db table name` | Название таблицы. Если не заданно, то используется имя сущности (`entity name`) приведённое ко множественному числу и snake_case | ❌           |
| `description`   | Детальное описание (опционально, может быть многострочным)                                                                       | ❌           |

🧩 **Методы настройки**

| Метод            | Назначение                                                  | Опционально |
|------------------|-------------------------------------------------------------|-------------|
| `.withLabels`    | Метки таблицы                                               | ✅           |
| `.withPK`        | Описывает [поля первичного ключа](#поля-таблицы)            | ✅           |
| `.withFields`    | Описывает [поля таблицы](#поля-таблицы)                     | ✅           |
| `.withRelations` | Описывает [отношения](#отношения) (one-to-one, many-to-one) | ✅           |
| `.withIndexes`   | Описывает [индексы](#индексы)                               | ✅           |

Пример определения таблицы:

```scala
.withTables(
  table("Country", "Country", "Country")
    .withPK(
      "id" :# "CountryId",
    )
    .withFields(
      "name" :# "Name",
      "key" :#? varchar(3) :@ "Country Key",
      dataElementTableField("LanguageId"),
      include("Modification")
    )
    .withIndexes(
      uniqueIndex("countryKey", "Country key must be unique", "key"),
    )
    .withRelations(
      manyToOne("languageId", "Reference to language", "Language", "languageId" -> "id")
        .withAssociation("language"),
    )
```

#### Поля таблицы

Поля таблицы задаются в разделах первичного ключа (метод `.withPK`) и в разделах полей (метод `.withFields`) определения
таблицы. Для поля таблицы задаются следующие параметры:

* имя поля в классе (структуре)
* [тип данных](#типы-данных) поля
* имя поля в таблице базы данных (по умолчанию равно имени поля приведённого к snake_case)
* наименование (краткое описание) поля (по умолчанию пусто)
* детальное описание поля (по умолчанию пусто)
* ограничение `NULL`/`NOT NULL` (по умолчанию поле `NOT NULL`)
* значение по умолчанию (по умолчанию не задано)
* параметры генерируемого столбца (по умолчанию не заданы)
* метки поля (по умолчанию не заданы)

Для создания поля используется следующий синтаксис:

| Синтаксис                                | Описание                                                                                                |
|------------------------------------------|---------------------------------------------------------------------------------------------------------|
| `"fieldName" :# datatype`                | Создаёт поле с именем `fieldName` и типом `datatype`                                                    |
| `"fieldName" :#? datatype`               | Создаёт поле с именем `fieldName` типом `datatype` и ограничением `NULL`                                |
| `"fieldName" :#++ datatype`              | Создаёт поле с именем `fieldName` типом `datatype` и генерацией `GENERATED ALWAYS AS IDENTITY`          |
| `dataElementTableField("dataElementId")` | Создаёт поле c параметрами (имя, тип, наименование и т.п.) из заданного элемента данных `dataElementId` |
| `include("includeId")`                   | Создаёт набор полей из заданного шаблона вставки `includeId`                                            |

Тип данных `datatype` может быть задан

* в виде значения указанного в разделе [Типы данных](#типы-данных),
* в виде строки `"dataElementId"` в этом случае параметры поля берутся из указанного элемента данных `dataElementId` (
  если они не определены в описании поля явно)

Для изменений параметров поля используется следующий синтаксис

| Синтаксис           | Описание                                                                                                              |
|---------------------|-----------------------------------------------------------------------------------------------------------------------|
| `:> "dbFieldName"`  | Задаёт имя поля в таблице базы данных `dbFieldName`                                                                   |
| `:@ "name"`         | Задаёт наименование (краткое описание) поля `name`                                                                    |
| `:@@ "description"` | Задаёт детальное описание поля `description`                                                                          |
| `:*(/* метки */)`   | Задаёт метки поля                                                                                                     |
| `:= default-value`  | Задаёт значение по умолчанию. Значение по умолчанию может быть строкой, числом или булевым значением                  |
| `:== "statement"`   | Задаёт значение по умолчанию в виде выражения `statement`. Например: `:== "CURRENT_TIMESTAMP"` - текущее время        |
| `:& modificatior`   | Задаёт параметры поля исходя из значения модификатора `modificatior`. Допустимые значения модификатора приведены ниже |

Допустимые значения модификатора:

| Модификатор                       | Описание                                                                           |
|-----------------------------------|------------------------------------------------------------------------------------|
| `Null`                            | Задаёт ограничение `NULL`                                                          |
| `AutoInc`                         | Задаёт параметры генерируемого столбца `GENERATED ALWAYS AS IDENTITY`              |
| `GenAlwaysAsIdentity`             | Задаёт параметры генерируемого столбца `GENERATED ALWAYS AS IDENTITY`              |
| `GenByDefaultAsIdentity`          | Задаёт параметры генерируемого столбца `GENERATED BY DEFAULT AS IDENTITY`          |
| `GenStoredAlwaysAs("statement")`  | Задаёт параметры генерируемого столбца `GENERATED ALWAYS AS( $statement ) STORED`  |
| `GenVirtualAlwaysAs("statement")` | Задаёт параметры генерируемого столбца `GENERATED ALWAYS AS( $statement ) VIRTUAL` |

#### Отношения

Отношения таблиц задаются в методе `.withRelations`. Для отношения задаются следующие параметры:

* идентификатор отношения
* наименование (краткое описание) отношения
* детальное описание отношения
* метки отношения
* тип отношения: `OneToOne`, `ManyToOne`
* идентификатор связанной таблицы
* связанные поля в виде списка `"fieldOfTableA" -> "fieldOfTableB"`
* действия `onUpdate`/`onDelete`: `Cascade`, `Restrict`, `NoAction`, `SetNull`, `SetDefault`. По умолчанию задаётся
  `NoAction`.
* признак логического отношения - логическое отношение не создаёт в БД ограничение `FOREIGN KEY`
* названия ассоциированных полей в структурах сущностей

Отношения описывается в следующем виде:

```scala
// реальное отношение OneToOne
oneToOne("id", "name", "relatedTableId", relatedFieldList)

// логическое отношение OneToOne
logicalOneToOne("id", "name", "relatedTableId", relatedFieldList)

// реальное отношение ManyToOne
manyToOne("id", "name", "relatedTableId", relatedFieldList)

// логическое отношение ManyToOne
logicalManyToOne("id", "name", "relatedTableId", relatedFieldList)
```

⚙️ **Аргументы и параметры**

| Параметр           | Описание                                                                               | Обязательно |
|--------------------|----------------------------------------------------------------------------------------|-------------|
| `id`               | Уникальный идентификатор отношения                                                     | ✅           |
| `name`             | Наименование (краткое описание) отношения                                              | ✅           |
| `relatedTableId`   | Идентификатор связанной таблицы                                                        | ✅           |
| `relatedFieldList` | Связанные поля в виде списка `"fieldOfTableA" -> "fieldOfTableB"`, разделённых запятой | ✅           |

🧩 **Методы настройки**

| Метод                             | Назначение                                                                                                              | Опционально |
|-----------------------------------|-------------------------------------------------------------------------------------------------------------------------|-------------|
| `.withDescription("description")` | Детальное описание отношения                                                                                            | ✅           |
| `.withLabels(/* метки */)`        | Метки отношения                                                                                                         | ✅           |
| `.withOnUpdate(foreignKeyAction)` | Действия `onUpdate`. Допустимые значения `foreignKeyAction`: `Cascade`, `Restrict`, `NoAction`, `SetNull`, `SetDefault` | ✅           |
| `.withOnDelete(foreignKeyAction)` | Действия `onDelete`. Допустимые значения `foreignKeyAction`: `Cascade`, `Restrict`, `NoAction`, `SetNull`, `SetDefault` | ✅           |
| `.withAssociation(association)`   | Названия ассоциированных полей в структурах сущностей                                                                   | ✅           |

Метод `withAssociation` позволяет определить ассоциативные поля в структурах сущностей.

Например, для отношения определённого в таблице `Country`:

```scala
manyToOne("languageId", "Reference to language", "Language", "languageId" -> "id")
  .withAssociation("language")
```

односторонняя ассоциация `language` означает, что в сущности `CountryEntity` будет добавлено поле
`Language *LanguageEntity` ссылающееся на сущность `LanguageEntity`.

Ассоциация может быть двухсторонней. Например, для отношения определённого в таблице `BusinessPartner`:

```scala
oneToOne("debtorId", "Reference to Debtor", "Debtor", "debtorId" -> "id")
  .withAssociation("debitor" -> "businessPartner")
```

двухсторонняя ассоциация `"debitor"  -> "businessPartner"` означает, что в сущности `BusinessPartnerEntity` будет
добавлено поле `Debitor *DebtorEntity`, ссылающееся на сущность `DebtorEntity`, а в сущности `DebtorEntity` будет
добавлено поле `BusinessPartner *BusinessPartner`, ссылающееся на сущность `BusinessPartnerEntity`

#### Индексы

Индексы таблиц задаются в методе `.withIndexes`. Для индексов задаются следующие параметры:

* идентификатор индекса
* наименование (краткое описание) индекса
* детальное описание индекса
* метки отношения
* признак уникального индекса `UNIQUE`
* поля индекса
* метод индексирования: `BTreeMethod`, `HashMethod`, `GistMethod`, `SpGistMethod`, `GinMethod`, `BrinMethod`
* условие индексирования `WHERE`
* список полей, которые войдут в индекс как неключевые столбцы

Индекс описывается в следующем виде:

```scala
// не уникальный индекс
index("id", "name", indexFields)
  .withDescription(description)
  .withLabels(/* метки индекса */)
  .withMethod(indexMethod)
  .where(predicate)
  .include(includeFields)

// уникальный индекс
uniqueIndex("id", "name", indexFields)
  .withDescription(description)
  .withLabels(/* метки индекса */)
  .withMethod(indexMethod)
  .where(predicate)
  .include(includeFields)
```

⚙️ **Аргументы и параметры**

| Параметр      | Описание                                                                                         | Обязательно |
|---------------|--------------------------------------------------------------------------------------------------|-------------|
| `id`          | Уникальный идентификатор индекса                                                                 | ✅           |
| `name`        | Наименование (краткое описание) индекса                                                          | ✅           |
| `indexFields` | Перечень полей индекса, разделённых запятыми. Детальное описания формата перечня полей см. ниже. | ✅           |

🧩 **Методы настройки**

| Метод                             | Назначение                                                                                                                      | Опционально |
|-----------------------------------|---------------------------------------------------------------------------------------------------------------------------------|-------------|
| `.withDescription("description")` | Детальное описание индекса                                                                                                      | ✅           |
| `.withLabels(/* метки */)`        | Метки индекса                                                                                                                   | ✅           |
| `.withMethod(indexMethod)`        | Метод индексирования. Допустимые значения: `BTreeMethod`, `HashMethod`, `GistMethod`, `SpGistMethod`, `GinMethod`, `BrinMethod` | ✅           |
| `.where(predicate)`               | Условие индексирования `WHERE`. Предикат `predicate` содержит логическое выражение. Например: `cor_tip IN ('I', 'U')`           | ✅           |
| `.include(includeFields)`         | Добавляет в индекс список полей, которые войдут в индекс как неключевые столбцы                                                 | ✅           |

Перечень полей индекса может быть определён используя следующий синтаксис:

| Синтаксис                     | Описание                                                                                                                         |
|-------------------------------|----------------------------------------------------------------------------------------------------------------------------------|
| `"fieldName"`                 | Индекс по полю `fieldName`, отсортированный в порядке возрастания.                                                               |
| `asc("fieldName")`            | Индекс по полю `fieldName`, отсортированный в порядке возрастания.                                                               |
| `desc("fieldName")`           | Индекс по полю `fieldName`, отсортированный в порядке убывания.                                                                  |
| `asc("fieldName").nullsFirst` | Индекс по полю `fieldName`, отсортированный в порядке возрастания и значения NULL после сортировки оказываются перед остальными. |
| `desc("fieldName").nullsLast` | Индекс по полю `fieldName`, отсортированный в порядке убывания и значения NULL после сортировки оказываются после остальных.     |

Пример:

```scala
index("filter", "Index to filter order by orderDate, customer & status", desc("orderDate"), "customerId", "status")
  .where("status <> 'DRAFT")
  .include("id", "postingDate")
,
```

### Структуры

Структуры используются для описания объектов DTO и операций с данными. Они описываются в следующем формате:

```scala
struct("id", "name", "struct name")
  .withDescription("description")
  .withLabels(/* метки таблицы */)
  .likeTable("tableId", fieldUsage)
  .likeTablePK("tableId")
  .withFields(/* определение полей */)
```

⚙️ **Аргументы и параметры**

| Параметр      | Описание                                                    | Обязательно |
|---------------|-------------------------------------------------------------|-------------|
| `id`          | Уникальный идентификатор структуры. Приводится к PascalCase | ✅           |
| `name`        | Наименование (краткое описание) структуры                   | ✅           |
| `struct name` | Имя структуры. Если не задано, то берётся из `id`.          | ❌           |
| `description` | Детальное описание (опционально, может быть многострочным)  | ❌           |

🧩 **Методы настройки**

| Метод                               | Назначение                                                                                                            | Опционально |
|-------------------------------------|-----------------------------------------------------------------------------------------------------------------------|-------------|
| `.withLabels`                       | Метки структуры                                                                                                       | ✅           |
| `.likeTable("tableId", fieldUsage)` | Формирует структуру включающую поля таблицы `tableId`. Правила включения полей определяются в `fieldUsage` (см. ниже) | ✅           |
| `.likeTablePK("tableId")`           | Формирует структуру включающую поля первичного ключа таблицы `tableId`                                                | ✅           |
| `.withFields`                       | Описывает [поля структуры](#поля-структур)                                                                            | ✅           |

Метод `likeTable` позволяет создать структуру аналогичную таблице `tableId`, указанной в методе. Для определения каки
поля из таблицы войдут в структуру используется правило `fieldUsage`:

| Правило                    | Описание                                                                                 |
|----------------------------|------------------------------------------------------------------------------------------|
| `IncludeAllFields`         | В структуру включаются все поля таблицы                                                  |
| `IncludePKFields`          | В структуру включаются все поля первичного ключа таблицы                                 |
| `IncludeFields(fieldList)` | В структуру включаются поля таблицы перечисленные в `fieldList`                          |
| `ExcludeFields(fieldList)` | В структуру включаются все поля таблицы за исключением полей перечисленных в `fieldList` |

#### Поля структур

Поля структуры задаются в методе `.withFields` определения структуры. Для поля структуры задаются следующие параметры:

* имя поля в классе (структуре)
* [тип данных](#типы-данных) поля
* наименование (краткое описание) поля (по умолчанию пусто)
* детальное описание поля (по умолчанию пусто)
* опциональность поля (по умолчанию поле не опциональное)

Для создания поля используется следующий синтаксис:

| Синтаксис                                 | Описание                                                                                |
|-------------------------------------------|-----------------------------------------------------------------------------------------|
| `"fieldName" :# datatype`                 | Создаёт обязательное поле с именем `fieldName` и типом `datatype`                       |
| `"fieldName" :##? datatype`               | Создаёт опциональное поле с именем `fieldName` и типом `datatype`                       |
| `dataElementStructField("dataElementId")` | Создаёт поле c параметрами (имя, тип, наименование и т.п.) из заданного элемента данных |
| `includeStructFields("includeId")`        | Создаёт набор полей из [шаблона вставки](#шаблоны-вставки) `includeId`                  |

Для изменений параметров поля используется следующий синтаксис

| Синтаксис           | Описание                                           |
|---------------------|----------------------------------------------------|
| `:@ "name"`         | Задаёт наименование (краткое описание) поля `name` |
| `:@@ "description"` | Задаёт детальное описание поля `description`       |

Тип данных `datatype` может быть задан

* в виде значения указанного в разделе [Типы данных](#типы-данных),
* в виде строки `"dataElementId"` в этом случае параметры поля берутся из указанного элемента данных `dataElementId` (
  если они не определены в описании поля явно)

Для структур которые ассоциированы с таблицами (используют метод `likeTable`) возможно использование типов данных
`linkedStruct` и `linkedStructArray`.

Тип данных `linkedStruct(structId, [relation])` добавляет в структуру новое поле ссылающееся на структуру `structId`.
Эта структура должна быть также ассоциирована с таблицей. Между двумя ассоциированными таблицами должно существовать
отношение (реальное или логическое), которое связывает эти таблицы. Если отношение между таблицами только одно, то его
можно не указывать. Если их несколько, то указание отношения `relation` обязательно. Допускается два варианта указание
отношения:

* `OwnRelation(relationId)` - отношение `relationId` определено в таблице ассоциированной с собственной структурой (т.е.
  структурой в которой определяется поле)
* `OwnRelation(relationId)` - отношение `relationId` определено в таблице ассоциированной со структурой `structId`)

Тип данных `linkedStructArray(structId, [relationId])` добавляет в структуру новое поле массив ссылающийся на структуру
`structId`. Эта структура должна быть также ассоциирована с таблицей. Между двумя ассоциированными таблицами должно
существовать отношение (реальное или логическое), которое связывает эти таблицы. Если отношение между таблицами только
одно, то его можно не указывать. Если их несколько, то указание отношения `relationId`, которое определено в таблице
ассоциированной с собственной структурой (т.е. структурой в которой определяется поле).

Использование типов данных `linkedStruct` и `linkedStructArray` позволяет установить связь между двумя структурами
которые ассоциированы с двумя связанными таблицами. Эта информация даёт возможность сгенерировать исходный код который
загрузит данные из двух таблиц в указанные структуры.

## Сборка модели и генерация артефактов

Для генерации артефактов необходима предварительная сборка модели данных, в ходе которой выполняются проверки
согласованности доменной модели: проверяются уникальность имен, существование связей, корректность
типов и многое другое.

Сборка выполняется следующим выражением:

```scala
val build = DomainBuilder.build(OrderDomain.data)
```

где `OrderDomain.data` доменная модель данных, описанная на Annette Data Dictionary DSL,

В зависимости от возвращаемого результата выполняется либо вывод ошибок (если модель их содержит), либо генерация
артефактов:

```scala
  build match {
  case Left(messages) =>
    // вывод ошибок
    messages.foreach(println)
  case Right(result) =>
    // вывод предупреждений
    result.warnings.foreach(println)
    // собранная модель данных может использоваться для генерации артефактов
    val domain = result.domain
  // ...
}
```

### DDL скрипты для PostgreSQL

Для генерации DDL скриптов PostgreSQL используется `PostgresDDLGenerator`:

```scala
import biz.lobachev.annette.data_dictionary.generators.Generator
import biz.lobachev.annette.data_dictionary.generators.postgres_ddl.PostgresDDLGenerator

Generator.generate(
  PostgresDDLGenerator(
    domain = domain, // Собранная модель
    filename = "pg_ddl.sql", // Имя файла генерируемого скрипта. Опционально. По умолчанию postgres_ddl.sql
  ),
  s"examples/${domain.id}/ddl", // Путь по которому будет находиться сгенерированный файл
)
```

### Исходный код Go

Для генерации исходного кода Go используется `GoGenerator`.

```scala
import biz.lobachev.annette.data_dictionary.generators.Generator
import biz.lobachev.annette.data_dictionary.generators.golang.{GoGenerator, GoGeneratorOptions, Gorm, Sqlx}

Generator.generate(
  GoGenerator(
    domain, // Собранная модель
    GoGeneratorOptions(options), // Опции генерации
  ),
  s"examples/${domain.id}/go", // Путь по которому будет находиться сгенерированные файлы
)
```

Опции генерации могут принимать следующие значения:

* `Sqlx` - генерация для библиотеки [sqlx](https://github.com/jmoiron/sqlx)
* `Gorm(fieldNullable)` - генерация для библиотеки [Gorm](https://gorm.io/). Если `fieldNullable = true` (по умолчанию),
  то для генерации `NULL` полей в сущностях используются указатели, в противном случае используется `sql.Null[T]`
